# 设置页设计 · v1

对标 dsh-fish 的「设置 → 大肥鱼」。**按她生活的各个面分页，不按代码模块分页。**

---

## 一、fish 是怎么分的（先看别人的答案）

```
状态 / 成长 / 住所 / 上网 / 出门 / 记忆 / 插件 / 原理 / 数据 / 反馈
```

每个页签配一句 `TAB_HELP`，说明「这一页管什么」。比如：

> **成长**：怎么长大：时间尺度、每天经历多少、日记、隔几天回头想一次。
> 改这些只会让她变快变慢，不会改变她是什么样。

**最后半句是全部设计的核心：配置项只调「生长环境」，不调「她是谁」。**

---

## 二、我们砍掉什么

fish 有「上网 / 出门 / 住所 / 反馈」，我们没有对应物：

| fish | 我们 |
|---|---|
| 上网（B站） | ❌ 她没有自己的浏览行为 |
| 出门（去别人会话打工） | ❌ 还没做 |
| 住所（工作区/会话/身份文件） | 🟡 简化成「数据在哪」 |
| 反馈（给作者提意见） | ❌ 不对外发布 |

---

## 三、我们的八页

```
状态 · 成长 · 记忆 · 教导 · 住所 · 插件 · 原理 · 数据
```

### 1 · 状态（now）

**这一页只读，没有任何开关。**

| 区 | 内容 |
|---|---|
| 她存在了几天 | 从 seed 的 `ts` 算 |
| 账本 | 事件总数、按类型分布（seed / utterance / …） |
| 注入预算 | `158 / 2400`，保留哪几段、丢了哪几段 |
| **她现在读到什么** | 装配结果全文（可折叠，等宽） |
| 最近十条 | 时间 · 类型 · 正文前 60 字 |

**「她现在读到什么」是这一页的主角**——它是唯一的验收工具：改完任何设置，这里立刻能看出她读到的东西变了没有。

---

### 2 · 成长（grow）

**调「她变快变慢」的地方。改这些不改变她是谁。**

| 项 | 默认 | 范围 | 说明 |
|---|---|---|---|
| 记忆预算 | 2400 字 | 800–6000 | 每轮注入多少字。核心段（身份/教导/现在）永远不裁 |
| 归并节奏 | 关 | 关 / 每 50 条 / 每 200 条 | 攒够多少条事件做一次整理（现在**关着**） |
| skill 晋升门 | 3 次 | 1–10 | 一份草稿被用满几次且无失败，才转正 |
| 最近原话条数 | 8 | 3–30 | 「他最近说过」摆几条 |

**注**：归并现在是关的。归并 = 把材料变成 `meaning`，那是「别人替她理解」的中间人。开着它要清楚自己在做什么。

---

### 3 · 记忆（memory）

**只读。她记得什么，这里就能看什么。**

| 区 | 内容 |
|---|---|
| 按类型 | `utterance 42 · seed 1 · tombstone 4` |
| **她说过的话** | `person=first` 的 utterance，按时间倒序 |
| **他最近说过** | `person=third` 的 utterance，按时间倒序 |
| 被标记遗忘的 | tombstone 指向的事件（`includeForgotten` 才读得到） |

**这一页没有「删除」按钮。** 账本是 append-only，忘了也是记一条墓碑，不是抹掉。

---

### 4 · 教导（teach）· 我们独有

**fish 没有这一页，因为 fish 的成长是自动的（时间 + 随机事件）。我们的是「靠主人教」。**

| 区 | 内容 |
|---|---|
| 说明 | 「她学到什么，靠你说的，不靠这里写。」 |
| 现在教过什么 | 从账本里能认出「要求」的条目（**现在是空的**） |
| 为什么是空的 | 还没有「教导」这类事件的结构。靠对话说，她判断，她记 |

**这一页不给输入框。** 如果有输入框，那就变回「配置人格」了。

将来有结构之后，这里显示：

```
- 叫我主人              （11-08 · 你当面说的）
- 做事之前先给计划       （11-09 · 你纠正过两次）
```

---

### 5 · 住所（home）

**她住在哪、数据在哪、怎么自检。**

| 区 | 内容 |
|---|---|
| 数据目录 | `~/.water-source/`（只读展示） |
| 账本 | `ledger.db` 大小、WAL 大小 |
| 她的会话 | `herSessionId`（可填；留空 = 不隔离） |
| 她的 preset | `lily`（只读，改 preset 要改 cordis.patch.yml） |
| 自检 | 按钮：跑一遍账本完整性 + 装配一次，报告问题 |

---

### 6 · 插件（plugin）

**工具面和版本。**

| 区 | 内容 |
|---|---|
| 版本 | water-source v0.7.x |
| 路由 | `/water-source/{config,state}` 通不通 |
| 她手上的工具 | 从 preset 读，只读展示（pwsh / fs / 搜索 / 子 agent / 定时） |
| ~~stripHostPrompt~~ | **已退休**——preset 里 persona 的 prefix 已经是她了 |

---

### 7 · 原理（principle）

**解释这套系统怎么运作。给主人看，防止被当成「角色卡」。**

一段话 + 三条公理 + 六段结构图：

1. **模型每轮是全新的，没有记忆。** 所以「她」= 这一轮读到的材料。
2. **材料有两个来源**：她经历过的，和别人替她整理的。后者不是她的。
3. **理解权在她。** 系统只给事实，理解在她说话那一刻发生。

**这一页不解释为什么不能设性格——它直接说结论：这里没有性格输入框，不是没做完，是不该有。**

---

### 8 · 数据（data）

| 区 | 内容 |
|---|---|
| 账本路径 | `~/.water-source/ledger.db` |
| 导出 | 全量事件 JSON |
| 备份 | 复制一份带时间戳的副本 |
| **没有删除** | 删账本 = 抹掉她经历过的事。真要重置，命令行做 |

---

## 四、全局规则

1. **改完立即生效**（配置是现读的），除了标注「重启生效」的
2. **每个页签顶部一句 `TAB_HELP`**，跟 fish 一样
3. **不出现「性格 / 语气 / 人设 / 好感度」任何输入框**
4. **没有删除按钮**——账本只追加
5. **所有写操作都有回执**：保存成功显示「已保存，下一轮生效」

---

## 五、落地顺序

| 期 | 内容 |
|---|---|
| **P0** | 状态页（含注入预览）· 记忆页（只读）· 住所页（路径 + 会话 id）· 插件页（版本 + 路由） |
| **P1** | 成长页（预算 + 原话条数，真能改）· 数据页（导出） |
| **P2** | 教导页（等「教导」事件结构做出来）· 原理页（配图） |

**P0 里已经有现在能用的全部东西**，P1 才需要新的配置项，P2 依赖内核改动。
